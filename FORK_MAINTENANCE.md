# Fork maintenance

This branch is maintained as a downstream Oxygen Customizer build while preserving the upstream
application/package identity for Xposed, overlay and user-data compatibility.

## Release signing

Do not publish a release with a temporary or debug signing key. The release workflows expect these
GitHub Actions secrets:

- `KEYSTORE` — base64-encoded release keystore
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS`
- `KEY_PASSWORD`

Telegram secrets are optional. Missing Telegram configuration must not fail a build.

The Android `applicationId` intentionally remains `it.dhd.oxygencustomizer`. Changing it is not a
single Gradle edit: Xposed initialization, AIDL packages, provider authorities, weather IPC, overlay
metadata, module paths and existing user data are coupled to that identity. Treat a future package
rename as a dedicated migration.

## Update channels

The app reads Beta and Nightly metadata from this fork. A channel is installable only when the
metadata contains a concrete artifact generated by this fork.

- Beta releases populate `latestBeta.json` and its SHA-256 during the signed release workflow.
- Nightly metadata is updated only after a signed Nightly artifact is produced.
- Until a fork-owned artifact exists, the corresponding in-app install action stays disabled.

This avoids accidentally installing an upstream APK signed with a different certificate.

## Compatibility strategy

OxygenOS private APIs change between OTAs even when the Android SDK level does not. New hooks should
prefer runtime capability checks (class/method/interface availability and `instanceof`) over SDK-only
assumptions. Reflected hook callbacks are guarded so an individual compatibility failure is logged
instead of being propagated into SystemUI or Launcher.

## Security boundaries

Exported components that are required for injected system processes are not public APIs:

- remote preferences validate caller UID/packages and only allow hooked hosts to write boot-loop
  health counters;
- weather and calendar providers restrict callers to the app/system consumers;
- advanced reboot authentication is derived from app-owned preferences, never from an Intent extra;
- update installation requires a one-time token, a trusted Downloads path, and (when supplied by
  release metadata) a matching SHA-256.
